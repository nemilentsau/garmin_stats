The findings pages show what the data revealed. This is the how. The fastest way to explain it is to follow one real investigation from start to finish — so most of this page does exactly that. No prior familiarity with the tools assumed.

The setup, in two minutes

The analysis was done with an AI coding agent — software you talk to in plain language that can also act: read the project’s files, write and run small programs, and draw charts. The catch is that, left to improvise, it is inconsistent — it might analyze the same data two ways on two days, or present a lucky fluke as a result. With personal health data, where it’s easy to “find” patterns that aren’t real, that’s the whole danger.

?

The one word to know: a “skill”

A skill is a written rulebook we hand the agent — durable, project-specific instructions it must follow for a kind of task. Not code that runs; guidance it reads and obeys every time. Skills are what turn an improvising assistant into a disciplined one.

The six skills we wrote — and the one that did this

Different layers of the project need different expertise, so we wrote six skills. Five support the work; one — finding-analyst — is the work this page is about, so the rest of the page just shows it running on one real investigation.

Inside finding-analyst

Four concrete pieces. Every investigation (a “run”) declares which kind it is, fills the same template files, claims a confidence level, and must clear the same gates.

1 · Three kinds of run — each must declare its plan up front

Run typeWhat it must commit to before touching dataCan it become a durable claim?
question-ledThe question. If it’s a true test: a written prediction + pass/fail rule first.Yes, if it reaches “confident”.
exploratoryWhich techniques (recipes) it will apply.Yes, if it reaches “confident”.
scoutA set of techniques, how broadly to sweep, and how to rank hits.No — it only feeds the question backlog.

2 · The template files every run fills in

“Templates” are fill-in-the-blanks documents copied into each run’s own dated folder, so every investigation is built — and can be re-read — the same way. They force the steps easiest to skip:

01-question.md
The question, dates, metrics — and, for a true test, the prediction and pass/fail rule written before any data is opened.
02-data-profile.md
Is the data even fit? Days present, what’s missing and where, how nulls and impossible values are handled.
03-analysis.py
The actual program — reads a frozen copy of the data and applies the declared recipes.
04-plots/
The charts, each labeled with units, dates, smoothing. These are the images on the findings pages.
05-findings.md
What we now believe: effect size, evidence, technique, the “so what”, caveats, and a confidence label.
06-review.md
An adversarial self-check against the gates. It may only lower a confidence label, never raise it.
07-findings-update.md
The exact line proposed for the permanent record — only if the finding earned it.

3 · The confidence ladder — it controls how far a finding travels

  • tentative One technique, no replication — or a lone hit from a wide scan. Stays in the run folder, never asserted.
  • provisional Several techniques agree, or a pre-registered test passed its decisive rule — but a real ceiling remains. Promoted as an attributed observation, caveats attached.
  • confident Provisional-grade with no remaining doubt, left standing by the review. Promoted as an asserted takeaway that can drive product decisions.

4 · The six gates a finding must clear

QuestionConcrete, dated, metrics fixed — and the prediction written before the data was opened?
DataSource pinned to a frozen copy; missing days measured; nulls and impossible values handled?
StatisticalEffect size before any p-value; spread and sample size shown; how many comparisons were made?
VisualEvery chart actually looked at; gaps not bridged into fake trends; a few values spot-checked by hand?
InterpretationA clear “so what”; confounders named; descriptive, never medical advice?
FindingsConfidence matches the evidence; date, sample size, and caveats recorded?

One real run, end to end

All of the above on a single real investigation: 2026-05-26-stress-hrv-lag — “does a stressful day predict a worse HRV the next night?” Here are its actual files.

1

The question — and the goalposts, fixed before any data

A true hypothesis test, so the prediction and the exact pass/fail rule were written first. This is the literal content of the run’s first file:

01-question.md  ·  run 2026-05-26-stress-hrv-lag written before any data
run type
question-led · hypothesis-test
question
Does an acutely high-stress day predict suppressed nightly HRV over the next 1–3 nights — beyond the well-known same-night relationship?
prediction
Higher stress on day D → lower HRV on nights D+1…D+3, strongest at +1, fading by +3.
decisive rule
The headline counts only if the next-night link survives holding the next day’s own stress constant — the partial correlation must reach |r| ≥ 0.10 with its 95% range excluding 0. Otherwise the verdict is “just the same-night echo.”
locked scope
Exactly 3 lags: +1, +2, +3. No adding lags or metric pairs after seeing the data.
recipes
“Does A predict later B?” + “Rule out a common cause” + missing-data pairing

Why this file exists: the definition of success is nailed down before a single number is seen, so the goalposts can’t move once results are in.

Check the data is fit, then run the declared techniques

On a frozen 357-day copy of the data, the run first confirmed the data could answer the question — stress complete (0% missing), HRV ~3.6% missing — and paired days only when they were truly consecutive (verified on a real gap at Nov 17→18, never bridged). Then it applied exactly the techniques it had declared, no more.

5

The adversarial review — which can only make the claim weaker

06-review.md  ·  the self-check against the six gates
All six gates passed — yet the confidence stayed provisional, not upgraded. The review is allowed to lower a claim, never raise it, and the shared-signal confound is a genuine ceiling, so “provisional” stands. (The review even flagged a contradiction in its own rulebook rather than smoothing it over — honesty over polish.)

A check that could only ever confirm what you hoped is not a check — so this one is built to push the other way.

↓
6

Promotion — the tier decides how far it travels

Because it landed at provisional (not confident), it entered the permanent record as an attributed observation with its caveats — this exact line:

“A high-stress day is a usable leading indicator that the next night’s HRV will read low… Use it for expectation-setting, not diagnosis… Provisional and predictive only — stress and HRV share an HRV-based derivation, so this is not an established independent causal channel.”

A confident finding would have become an asserted takeaway; a tentative one would have stayed in the folder, unpublished. That is the whole machine: a question with fixed goalposts, named techniques, a labeled chart, and a review that can only make the claim weaker. Every chart in the findings came down this same path.

The technique catalog

That run reached for three techniques. Each is a written recipe — what it asks, and the specific trap it’s built to avoid. Pick one to see it in plain terms with a real chart it produced. (green = battle-tested in a trusted run; grey = written and sound, not yet relied on.)

Missing-data pattern

validated

When did a sensor stop recording — and do the gaps line up with anything that would change how we read the data?

It asks
“Which days are missing for each metric, and are the gaps random or clustered?”
The trap it avoids
Treating a gap (no reading) as if it were a real low value, or mistaking an early device-setup gap for a health event.
First proven in
the full-dataset baseline run (2026-05-26).

→ Produced the coverage finding on General: the autonomic core is complete, SpO₂ has two structural gaps.

Distribution shape

validated

Does a metric cluster around one typical value, or two? Is it lopsided?

It asks
“Is this one hump or two — a single state, or a switch between two?”
The trap it avoids
A “two-humps” call is checked three independent ways (a shape number, a model comparison, the naked eye) and re-checked inside a single calm period — since two apparent humps are usually just two seasons blended together.
First proven in
the HRV bimodality run (2026-05-27).

→ Produced the headline HRV finding on HRV: it is one continuous signal, not two modes.

Correlation sweep

validated

Across all the metrics at once, which ones move together?

It asks
“For every possible pair of metrics, how strongly do they rise and fall together?”
The trap it avoids
It uses a measure a few outliers can’t distort and treats every hit from such a broad scan as a lead to check, never a conclusion.
First proven in
the full-dataset baseline run (2026-05-26).

→ Produced the central result on General: almost everything collapses onto one recovery↔stress axis.

Does A predict later B?

validated

Does today’s value of one metric predict tomorrow’s — or next week’s — value of another?

It asks
“Does metric A on a given day relate to metric B one, two, … days later?”
The trap it avoids
Days are paired only when truly the right number of days apart (never bridging a gap), and because today echoes yesterday, the confidence range uses a method built for streaky data.
Used by
the worked example above (2026-05-26-stress-hrv-lag).

→ Produced the lead-indicator finding on HRV: a hard day predicts a low HRV the next night.

Rule out a common cause

validated

Does A still relate to B once we hold a likely shared cause constant?

It asks
“Is this a direct link — or are both metrics driven by a third thing?”
The trap it avoids
Holding a third factor constant removes only its simple influence; if two metrics share a raw source, a surviving link may still be that shared origin — so it says so rather than claiming independence.
First proven in
the SpO₂ incremental-value run (2026-05-26).

→ Produced the “not a recovery signal” finding on General: overnight SpO₂ is a health flag, not a recovery input.

Unusual-stretch scan

validated

Were there stretches of days when many metrics were unusual at the same time?

It asks
“Scanning the whole year, which windows show simultaneous deviation across several metrics?”
The trap it avoids
“Unusual” is measured against your personal normal, and the rule is rank, then look: every flagged window is overlaid on the full timeline before it’s believed.
First proven in
the full-dataset baseline run (2026-05-26).

→ Produced the regime map on General and pinpointed the November low-recovery crash.

When did “normal” shift?

validated

When exactly did a metric’s baseline level change — and when did it return?

It asks
“Where are the edges of a regime — its start, and the day it truly ended?”
The trap it avoids
“Returned to normal” is defined strictly as after the last bad day, so a brief mid-slump rebound can’t be mistaken for the end.
First proven in
the November regime-extent run (2026-05-26).

→ Produced the regime-extent finding on Recovery: the November crash is a five-week event.

Best vs worst stretch

validated

What separates the best stretch of the year from the worst, and by how much?

It asks
“Put two periods side by side — how big is the difference on each metric?”
The trap it avoids
Picking the windows by an outcome and then “testing” on the same data is circular — so the run declares up front how the windows were chosen.
First proven in
the full-dataset baseline run (2026-05-26).

→ Produced the “why one composite” evidence on Recovery: the metrics are all suppressed together.

Is one day an outlier?

candidate

Is a single dramatic day-over-day move genuinely unusual — and what moved with it?

It asks
“How rare is this one-night change, and did other metrics move the same night?”
The trap it avoids
A single day can’t replicate, so it’s the weakest evidence; coverage is checked first, since a nightly number can jump from a short night, not the body.
Status
candidate — sound, not yet leaned on by a trusted run.

→ Produced the February case study on HRV: a single night can crash and rebound — read the trend, not the night.

Is the structure stable?

validated

Do the relationships between metrics stay the same in good periods and bad ones?

It asks
“Is the underlying pattern linking the metrics the same in a crash as in a calm month?”
The trap it avoids
It pre-commits that a mere weakening of links (not a reshaping) does not count as instability.
First proven in
the axis loading-stability run (2026-06-11).

→ Produced the “same axis everywhere” finding on General: one fixed scoring is justified.

What counts as “normal”?

validated

Should “normal for you” be your whole history, or a rolling recent window?

It asks
“Which definition of a personal baseline correctly flags a known-bad month?”
The trap it avoids
It judges candidates on a scorecard fixed in advance, and includes a deliberately “cheating” hindsight baseline — if even that fails a test, the test is measuring the wrong thing.
First proven in
the normalization-baseline run (2026-06-11).

→ Produced the most counter-intuitive choice on Recovery: use an expanding personal baseline, never a trailing window.

Types, or a spectrum?

validated

Do days fall into a few distinct “types”, or form one smooth spectrum?

It asks
“Are there real recovery-day archetypes, or just degrees along a single scale?”
The trap it avoids
Grouping software always returns groups — so extra tests are run that can tell a genuine type from an arbitrary slice of a spectrum. Here they found a spectrum.
First proven in
the recovery day-states run (2026-06-11).

→ Produced the “no archetypes” finding on Recovery: recovery is a continuum, not discrete states.

Pick the best label rule

candidate

A label shown in the app looks unreliable — which replacement rule is best?

It asks
“Lined up on one fair scorecard, which candidate rule is most sensitive and least jumpy?”
The trap it avoids
The current rule is run exactly as shipped as the baseline, every candidate is scored identically, and a “no-label-at-all” option is always included — because often the labeling itself, not where the line is drawn, is the problem.
Status
candidate — already used once (2026-06-18), kept provisional until more runs rely on it.

→ Produced the cue redesign on HRV: show a continuous signal, drop the status word.

Real weekly rhythm?

candidate

Is an apparent day-of-week pattern real, or just noise?

It asks
“After removing slow seasonal drift, is there a genuine weekday effect?”
The trap it avoids
Streaky data manufactures fake cycles, so significance uses a method that respects that streakiness, and it names the calendar label rather than guessing the cause.
Status
candidate — the careful version of an earlier, weaker analysis it replaced (2026-06-18).

→ Produced the weekly-rhythm finding on HRV: a real ~10 ms day-of-week swing.

That’s the whole method

Skills give the agent durable rules; finding-analyst’s templates force every run through the same honest steps; recipes supply vetted techniques with their traps attached; and the confidence ladder decides what gets asserted. See it in the results on General, Recovery Score, and HRV.
