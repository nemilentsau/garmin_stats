# Block 0 Phase 0 — Translation, Typed Check-in, Branch Log, v2 Kill

**Status:** Design approved in conversation 2026-07-07
**Governed by:** `docs/routine-pivot/pivot_roadmap.md` (Phase 0, rev. 2026-07-07); source of truth is `docs/routine-pivot/{general_principles.md, schema_v3_spec.md, block0/}`
**Goal:** Block 0 (window 2026-07-06 → 2026-08-02) executes on the current v2 engine with trustworthy capture before day 8 (2026-07-13), and the dead v2 training content is retired.

Four deliverables, one package:

## 1. Translation script: v3 sources → derived v2 bundle

`scripts/translate_block0.py` reads `docs/routine-pivot/block0/{running_v3,strength_v3,support_v3,block0,exercise_library}.json` and writes **one** derived bundle `docs/routine_bundles/block0_v3_derived.json` (`schema_version: 2`). The output is a build artifact: regenerated on any source change, never hand-edited (its `description` says so). It is committed so `scripts/import_bundles.py` and the API import work anywhere.

**Structure:** 15 card templates (6 running + 6 strength + 3 support) + 1 routine spec (`start_date: "2026-07-06"`, 88 assignments, `day` 1–28 relative, slots morning/midday as authored).

**Card mapping:**

| v3 | v2 card_type | Notes |
|---|---|---|
| `run.*` (6) | `running_workout` | segments → `RunSegment` with rendered prescription strings ("7 mi @ Z1–Z2"); kind by label (warmup/strides/cooldown/else main). LTHR test = running card whose segments carry the protocol and whose instructions carry the quality gate (dew point ≤ 22 °C, strap ≥ 95%). `post_run_fields: []` (P7 — dew point is ambient). |
| `str.*` (6), `sup.hsr_*` (2) | `strength_session` | exercises → `StrengthExercise` {id, label from `exercise_library.json`, `set_scheme` rendered "4×5–8 @ RPE 8", `detail` from tempo/technique}. `rating_prompts: []` (no consumer). Card-level `rir_guidance` notes RPE↔RIR equivalence (prescriptions say RPE, the set log captures RIR). |
| `sup.daily` | `checklist` | 6 `tissue_check` items (quad, glute, hamstring, calf/achilles, soleus, tibialis/foot) + 1 checkbox (`core_done`, "habitual core + mobility done, ≤15 min"). Sorts first in the morning slot (`position`). |

**Per-day variation** (v3 assignments patch prescriptions per day; a v2 template is static): each assignment's `prescription_override_json` carries that day's rendered fields — segment strings for the full variant, plus the two new payload fields below. Override keys are already validated per payload type at activation.

**Selection rules → two new optional payload fields** (on `RunningWorkoutPayload`, `StrengthSessionPayload`, `ChecklistPayload`):
- `variant_options: list[str] = []` — the v3 assignment's variant ids in order (e.g. `["full","reduced","skip"]`; upper cards add `"plus"`; the day-16 LTHR backup carries its `alternate_strides` branch as an option).
- `selection_rule: str | None = None` — deterministic English rendering of the v3 decision list, generated by the translator from the predicates ("Skip if quad flag, glute flag, or HRV < −1.5 SWC; Reduced if HRV < −0.75 or quad soreness ≥ 2; otherwise Full. Missing data → conservative.").

The translator follows `compiled_schedule.json` for what lands on each day (it is the linted truth, including the day-12 test and day-16 backup); `key_session: true` (the long run) renders as a line in the day's instructions. Weekly sanity check in the script: recompute per-week run miles from the emitted assignments and assert 49.0/49.5/49.0/32.8 (matching `lint_report.json`) — translation drift fails loudly.

## 2. Typed morning check-in (checklist card extension)

Contract (`backend/app/domains/routines/contracts.py`):
- `ChecklistItem` gains `kind: Literal["checkbox", "tissue_check"] = "checkbox"`.
- `ChecklistAnswer` gains `scale: int | None = None` (0–3) and `flagged: bool = False`; `checked`/`text` unchanged. Existing tolerant normalization keeps old logs valid.

UI (`ChecklistCard.svelte`): `tissue_check` items render as a compact row — tissue label, 0/1/2/3 segmented chips (default 0), flag toggle ("pain above background noise"). A clean morning is five seconds of confirmation. Checkbox items render as today. Both Today and Schedule surfaces via the existing dispatcher.

Deferred (noted, not built): weekly `bodyweight` capture (feeds `est.physique` in Phase 1) — not part of the v3 check-in card's capture list; Phase 1 decides its surface.

## 3. Branch log: `variant_taken` on card logs

- `CardLog`, `TodayCardLogUpdateRequest`, `TodayCard` gain `variant_taken: str | None = None`.
- Log-mode UI: when the card payload has `variant_options`, render a segmented control above the capture fields; `selection_rule` renders as one muted line under the card header in both modes. Selecting `skip` auto-suggests status `skipped` (still user-editable); other variants leave status alone.
- No rule evaluation, no enforcement — this is a *log*, the human is the selector for Block 0 (roadmap D2). Phase 1's event log inherits real branch data instead of free-text archaeology.

## 4. Kill the v2 training content

- **DB backup first** (hard rule after the 2026-06 import incident): copy `storage/garmin_stats.db` to a dated sibling before any mutation.
- `scripts/retire_routines.py`: re-saves the five training routine schedules with `status: "retired"` — `four-week-running-calibration-patched-routine`, `four-week-running-meditation-transfer-routine`, `four-week-running-support-calibration-routine`, `four-week-strength-running-calibration-routine`, `two-week-core-foundation-routine` — plus their card templates (by the template-id lists of those five bundles). Read paths already filter `status="active"`, so Today/Schedule drop them immediately. **`card_logs` are never touched** — history stays for experiments and review.
- Delete the five training bundle JSONs from `docs/routine_bundles/`. Keep `four_weeks_breathwork.json`, `four_weeks_meditation.json`, `two_week_meditation_bundle.json`, and the three experiment specs — the O2 track runs unchanged (roadmap Phase 3).

## Order of operations

Contract changes (2, 3) → regenerate API types → frontend (check-in rows, variant control, rule line) → translator + derived bundle → retire script + backup → import & activate Block 0 → visual verification of Today board (day N of Block 0) against `schedule_overview.md`, including logging a tissue_check answer and a variant, and confirming retired routines are gone while meditation/breath cards remain.

## Non-goals

- No v3 runtime (selection evaluation, signals, estimators, event log) — Phase 1, during the block.
- No changes to breath/meditation cards, experiments, or the dashboard.
- No `anytime`-slot or recurrence features; Block 0 uses morning/midday only.
